Problem Statement

Traditional Excel-based DCF models are brittle, non-reproducible, and impossible to validate at scale. When NVIDIA's revenue grew 122% YoY in FY2024, every formula in a linked workbook required manual review — one broken cell reference cascades silently with no audit trail.

Five core failures this project solves

  • No schema enforcement — renamed columns break everything silently
  • No audit trail for missing-data decisions
  • Scenario switching requires manual copy-paste
  • KPI thresholds undocumented and inconsistently applied
  • No automated regression testing for financial formula logic

How this project solves them

  • Canonical schema + typed Parquet tables with strict column validation
  • Guaranteed error_report.csv on every ETL run
  • Delta-only JSON scenario engine, base assumptions never mutated
  • NVIDIA-calibrated traffic-light KPIs with documented thresholds
  • Full pytest suite: ETL, invariants, KPI formulas, golden output
02

Architecture — 4-Layer System

Every layer has a single responsibility and communicates with the next via explicit data contracts. Business logic is strictly prohibited from the UI layer.

L1

Data Layer — Raw Source Files

13 raw XLSX/CSV files sourced from NVIDIA SEC EDGAR filings: annual Income Statement, Balance Sheet, and Cash Flow (FY2020–FY2025), quarterly versions of all three, segment revenue breakdown (Data Center, Gaming, Professional Viz, Automotive, OEM), working capital schedule, peer comparables, and market data. Every number traces back to an audited 10-K filing. CF data for FY2020–2021 is genuinely absent from NVIDIA's filing presentation — this is documented explicitly as a business fact, not a data quality gap.

L2

ETL Pipeline — 7 Stages

A modular, stage-separated pipeline where each Python module has exactly one responsibility. Stage 1: loader.py handles raw CSV I/O only. Stage 2: transformer.py maps 60+ column name synonyms across Bloomberg, FactSet, SEC EDGAR, and Excel exports to a single canonical schema. Stage 3: validator.py enforces schema, detects exact vs conflicting duplicates, and checks financial business rules (BS balance, CF reconciliation). Stage 4: cleaner.py applies an explicit per-column missing-value policy (error/zero/ffill/bfill/median/warn/ignore) — no implicit defaults anywhere. Stage 5 derives IS ratios. Stage 6 builds and merges canonical tables. Stage 7 persists outputs as Parquet. error_logger.py guarantees an audit CSV on every run, including failures.

L3

Computation Layer — KPI Engine + DCF Model

All KPI functions in kpis.py are pure functions accepting scalars and returning scalars — no DataFrames, no side effects, no global state. A single safe_divide() gateway handles every division, returning None (not NaN, not exception) on zero denominators. Eight core KPIs computed: Gross Margin, EBITDA Margin, FCF, FCF Margin, Revenue Growth, AR Days (DSO), AP Days (DPO), Current Ratio. Traffic-light signals in ratios.py are calibrated to NVIDIA's FY2020–2025 ranges. The DCF model implements FCFF discounting with end-of-year convention, Gordon Growth terminal value, and a full 9×9 sensitivity grid across WACC and terminal growth rate. Scenarios are powered by a deep-merge JSON engine — base assumptions never mutate.

L4

Presentation Layer — Streamlit Dashboard

app.py handles routing and filtering only — zero business logic. kpi_tile.py renders pre-computed scalars from the KPI engine into signal-colored cards with delta vs prior year. Scenario switching is live. Filters: fiscal year slider, KPI selector, margin selector. Plotly charts for KPI and margin trends.

03

Data Collection & ETL Detail

Canonical tables produced by the pipeline

actuals.parquet

Full consolidated IS + BS + CF merged on fiscal_year. 96 columns, 6 rows (FY2020–FY2025). Downstream modules read exclusively from here — never from raw files.

costs.parquet + working_capital.parquet

Income statement cost structure and NWC schedule (DSO/DIO/DPO/CCC) with both historical actuals and scenario-tagged forecasts. PKs enforce data integrity.

Key ETL engineering decisions worth explaining in an interview

  • Parquet over CSV for canonical storage: preserves dtypes exactly (no silent float→string coercion), 3-10× smaller, significantly faster reads. CSVs generated alongside for human inspection only.
  • Conflicting duplicates raise immediately, never silently resolved. Same fiscal_year + different revenue = data corruption, not a noise problem. Exact duplicates (byte-for-byte identical from export bugs) are deduplicated and logged.
  • Per-column missing value policy in a single dict: revenue_usdm = "error", acq_termination_usdm = "zero" (fabless company, structurally absent most years), accounts_receivable_usdm = "ffill" (balance sheet items change slowly), cfo_usdm FY2020-21 = "ignore" (genuinely absent from NVIDIA's 10-K format, not a gap).
  • Column mapping covers 60+ synonyms: "revenue", "total_revenue", "net_sales", "revenues", "net revenues" all map to "revenue_usdm". Any column not in the mapping is dropped with a warning — no silent pass-through.

DCF Valuation Engine

Methodology

  • 5-year FCFF projection (FY2026F–FY2030F)
  • NOPAT = EBIT × (1 − effective tax rate)
  • FCFF = NOPAT + D&A − CapEx − ΔNWC
  • End-of-year discounting: PV(t) = FCFF(t) / (1+WACC)^t
  • Gordon Growth terminal value: TV = FCF₅ × (1+g) / (WACC−g)
  • EV → equity bridge → implied price per share
  • 9×9 sensitivity grid (WACC × terminal growth rate)

Financial Invariants & Validation

Three non-negotiable accounting identities tested against real NVIDIA data on every CI run. If any fails, the model or source data is wrong.

1

Balance Sheet Identity

Total Assets = Total Liabilities + Shareholders' Equity | Tolerance: $0.01M

Verified for all 5 BS years (FY2021–FY2025). FY2025: $111,601M = $32,274M + $79,327M ✓. Tolerance matches data_contracts.md Rule 2. Broken BS data fixture confirmed the guard catches corruption.

2

Cash Flow Reconciliation

CFO + CFI + CFF = Net Change in Cash | Tolerance: $0.01M

Verified for FY2022–FY2025. FY2025: $64,089 + (−$20,421) + (−$42,359) = $1,309M ✓. FY2020–2021 rows skipped (NaN by architecture design). FCF sub-invariant: FCF = CFO + CapEx (CapEx stored negative).

3

Retained Earnings Rollforward

RE(t) = RE(t−1) + Net Income(t) − Distributions(t)

Distributions dominated by buybacks ($33.7B in FY2025). Implied distributions = RE_prior + NI − RE_current. FY2025: $68,038M = $29,817M + $72,880M − $34,659M ✓. Validates equity section integrity across all 4 intersecting years.

07

Testing Strategy

4 test modules, 3 testing philosophies

  • test_kpi_formulas.py — Known-value testing: every formula tested against FY2025 10-K actuals (e.g., gross margin must equal 0.7499 ± 0.001, not just "is a float")
  • test_financial_invariants.py — System-level invariant testing: mathematical identities that must hold across the full dataset regardless of inputs
  • test_etl_validation.py — ETL guard testing: schema, duplicates, missing-value policy, business rules
  • test_golden_output.py — Regression testing: canonical table structure and row-count assertions catch silent ETL regressions

Edge case coverage

  • None inputs → None output (never NaN, never crash) for all 8 KPIs
  • Zero denominator → None from safe_divide() gateway
  • Exact duplicates → silently removed + logged to error_report
  • Conflicting duplicates → ValueError raised immediately
  • CF NaN for FY2020-21 → allowed by "ignore" policy, not raised
  • Inventory NaN → filled with 0 (NVIDIA is fabless, structurally valid)
  • AR NaN → forward-filled from prior year (slowly-changing BS item)

Tech Stack & Infrastructure

Python 3.11+ Streamlit 1.35+ Pandas 2.0+ Plotly 5.20+ PyArrow 15+ SciPy 1.13+ pytest 8.0+ pytest-cov black + isort + flake8 + mypy Docker (multi-stage) GitHub Actions CI PyYAML + jsonschema openpyxl

Infrastructure decisions worth discussing

  • Multi-stage Docker build: builder stage with gcc/g++ for PyArrow/SciPy compilation → lean python:3.11-slim runtime image. Compiler toolchain is a security surface area; stripping it from the runtime image is not optional.
  • Pandas over Polars/Spark: NVIDIA has 6 annual rows. Spark is designed for distributed processing of data that won't fit in memory. Introducing it here would add a JVM dependency and a cluster management problem with zero benefit.
  • Delta-only scenario JSON: 3 full copies of an assumptions file drift. The upside WACC gets updated; the downside one doesn't. Delta-only overrides via recursive deep_merge make all changes explicit and minimal — same pattern as Kubernetes Helm chart value overrides.
  • Version-pinned requirements: Pandas 3.0 introduced breaking changes to DataFrame merging semantics. Pinning to <3.0 captures all security patches while blocking breaking changes.

Interview defence — questions you should expect

Why raise on conflicting duplicates?

Two revenue figures for FY2023 is data corruption. There is no automatic resolution that is correct — keep_first or keep_last is an arbitrary choice that permanently corrupts the model with no audit trail.

Why is inventory policy "zero"?

NVIDIA is a fabless semiconductor company — they design chips but outsource manufacturing to TSMC. Inventory is structurally minimal. Filling NaN with 0 is not a data quality fix; it's the correct business representation.

Why end-of-year discounting, not mid-year?

The Excel model formula on 05b_DCF row 8 is =H5/(1+$C$14)^H7 where H7 is the projection year number (1–5). No 0.5 offset. Standard academic DCF convention, not Damodaran mid-year style.

Why -40% upside/downside?

The valuation date is October 17, 2025. The $183.22 market price reflects AI hype premium. The base case DCF at 12.91% WACC and 4% terminal growth implies $109.26 — a more conservative long-run normalised view. The model is not a trading signal; it's a structured discipline check.

Why does RE rollforward matter?

The retained earnings rollforward is the plug mechanism that makes the balance sheet close in forecast years. RE(t) = RE(t-1) + NI(t) - Distributions(t). If distributions (dividends + buybacks) are miscalculated, the BS goes out of balance and the CF statement mis-reconciles — silent cascade failure.

How would you scale this to multi-company?

The canonical schema already carries ticker, is_forecast, scenario, and source columns. Multi-company extension requires only additional data loading and Parquet partitioning by ticker. The modeling layer, KPI engine, and dashboard are already ticker-agnostic architecturally.
